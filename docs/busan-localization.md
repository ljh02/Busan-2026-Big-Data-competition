# 서울 → 부산 지역 전환 계획

작성일: 2026-09-04

**2026 BIG DATA 활용대회**의 공모 주제가 "공공데이터 및 오픈맵 데이터를 활용한
**부산지역** 현안 분석"으로 못박혀 있다. 현 BalueWave 구현은 서울 데이터셋 위에 서
있으므로 지역 전환이 **주제 적합성의 전제조건**이다.

이 문서는 무엇이 서울에 묶여 있는지와, 무엇이 있어야 풀리는지를 적는다.

---

## 🔴 왜 아직 전환하지 않았는가

**부산 실데이터가 없으면 전환은 조작이 된다.**

서울 데이터를 부산 지명으로 갈아끼우는 것은 5분이면 된다. 그러나 그렇게 만든
"부산 서면 월세 57만원, 통근 24분"은 **근거 없는 숫자**다. 대회 심사 대상이 데이터
분석 결과인 이상, 허위 수치가 들어간 제출물은 성립하지 않는다.

따라서 **코드의 지명만 바꾸는 부분 이관은 하지 않았다.** 아래 A·B 를 확보한 뒤
한 번에 전환하는 것이 맞다.

---

## 전환 대상 인벤토리

### A. 실데이터가 필요한 것 (블로킹)

| 대상 | 현재 | 필요한 부산 소스 |
|---|---|---|
| `data/areas.actual.json` | 서울 생활권 **9곳** (건대입구·신림·청량리·왕십리·구로디지털단지·공덕·마곡나루·상암DMC·김포공항) — 2025 전월세 시세, 통근시간, 생활 SOC 집계 | 부산 생활권 선정 + 전월세 시세 + 통근시간 실측 |
| `data/apartments.seoul.snapshot.json` (1.7MB) | 서울 열린데이터광장 `OpenAptInfo` 단지 스냅샷 | 부산 공동주택 단지 정보 (부산 공공데이터포털) |

이 둘이 서비스의 사실 기반 전부다. **여기가 채워지기 전에는 나머지를 바꿔도 화면이
동작하지 않는다** — `areas.actual.json` 의 `commuteMinutes` 키가 `DESTINATIONS` 키와
1:1로 묶여 있어서, 한쪽만 바꾸면 통근시간이 전부 누락된다.

### B. API 어댑터 교체 (소스 확인 필요)

| 파일 | 현재 바인딩 | 전환 방향 |
|---|---|---|
| `api/apartment_adapters.py` | `openapi.seoul.go.kr/…/OpenAptInfo` | 부산 공동주택 정보 API |
| `api/seoul_air_adapters.py` | `openapi.seoul.go.kr/…/ListAirQualityByDistrictService` | **에어코리아(한국환경공단) 전국 API** 로 바꾸면 지역 종속이 사라진다 — 권장 |
| `api/public_cctv_adapters.py` | 서울 CCTV | 부산 CCTV / 안전 데이터 |
| `scripts/build_apartment_snapshot.py` | 서울 `OpenAptInfo` 수집기 | 부산 소스로 재작성 |
| `scripts/build_real_dataset.py` | `datafile.seoul.go.kr` | 부산 소스로 재작성 |

> 파일명에 `seoul` 이 박힌 모듈(`seoul_air_adapters.py`)은 리네임 대상이다.
> 에어코리아 전국 API 로 가면 `air_adapters.py` 로 일반화하는 편이 낫다.

### C. 그대로 두는 것

- **`api/real_estate_price_adapters.py` — 국토교통부 실거래가 API.** 전국 API 다.
  법정동코드 `LAWD_CD` 를 부산 자치구(`26***`)로 바꾸면 그대로 동작한다.
  이전 공모전의 흔적이 아니라 데이터 출처이므로 **삭제하면 안 된다.**
- **Leaflet + OpenStreetMap.** 대회가 요구하는 "오픈맵 데이터"를 이미 충족한다.
- **추천 알고리즘·가중치·페르소나.** 지역 무관.
- **`api/route_adapters.py` (Kakao/ODsay/TMAP).** 전국 서비스다. 좌표만 부산으로.

### D. 코드 상수 (A 확보 후 동시 교체)

`api/baluewave_api.py`

- `DESTINATIONS` — 서울 업무지구 5곳(강남·여의도·서울역·구로디지털단지·판교)
- `AREA_ADDRESSES` — 서울 생활권 9곳 주소

부산 업무지구 후보(확정 전, 실측 필요): **서면**(부산진구), **센텀시티**(해운대구),
**부산역·중앙동**(동구/중구), **문현금융단지**(남구), **녹산국가산단**(강서구).

## 권장 순서

1. **부산 공공데이터포털에서 확보 가능한 데이터셋을 먼저 확정**한다.
   — 무엇이 있는지가 생활권 선정과 지표 설계를 좌우한다.
2. 대기질을 **에어코리아 전국 API** 로 먼저 일반화한다 (지역 종속 1건 제거).
3. 부산 생활권 9곳을 선정하고 `areas.actual.json` 을 실데이터로 생성한다.
4. 부산 아파트 단지 스냅샷을 생성한다.
5. `DESTINATIONS` / `AREA_ADDRESSES` 를 3~4 와 **같은 커밋에서** 교체한다.
6. 통근시간을 ODsay/TMAP 실호출로 채운다.

---

## 미확인 사항

- 부산 공공데이터포털의 공동주택 단지 정보 API 존재 여부와 스키마
- 대회가 지정·제공하는 데이터셋이 따로 있는지 (공식 공고문 미확보)
- 부산 자치구별 `LAWD_CD` 정확한 값

**추정으로 채우지 말 것.** 확인되는 대로 이 문서를 갱신한다.
